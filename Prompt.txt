# Build a Demo MVP: AI Code Security Analyzer

Build a **working demo MVP** for our cybersecurity research project:

> **AI Code Security Analyzer — Detecting Security Vulnerabilities in AI-Generated Software**

The goal of this MVP is to demonstrate that our system can take an **entire software project**, scan its source files, identify potential security vulnerabilities, explain the findings, and provide remediation suggestions.

This is a **review/demo version**, so prioritize reliability, clean architecture, and an impressive working UI over advanced research features.

---

# 1. CORE DEMO

The application must support this workflow:

```text
User uploads project ZIP
        ↓
ZIP extraction
        ↓
Project structure analysis
        ↓
Identify supported source files
        ↓
Scan files recursively
        ↓
Run security detection rules
        ↓
Normalize findings
        ↓
Deduplicate findings
        ↓
Generate project security report
        ↓
User explores vulnerabilities
        ↓
Show evidence + explanation + remediation
```

The system must scan the **whole project**, not just one pasted code snippet.

# 5. PROJECT ZIP UPLOAD

The backend must accept ZIP files.

Endpoint:

```text
POST /api/projects/scan
```

The ZIP should be:

1. validated
2. safely extracted
3. recursively traversed
4. source files identified
5. ignored directories skipped
6. files scanned
7. findings returned

---

# 6. SECURITY FOR ZIP PROCESSING

This is extremely important.

Do NOT blindly extract ZIP files.

Protect against:

### Zip Slip / Path Traversal

Reject entries such as:

```text
../../evil.py
```

or absolute paths.

All extracted files must remain inside the temporary project directory.

Also enforce:

* Maximum ZIP size: 25 MB
* Maximum extracted size: 100 MB
* Maximum number of files: 2,000
* Ignore symbolic links if possible
* Reject dangerous archive structures

The system should NEVER execute uploaded project files.

We are performing **static source analysis only**.

# 13. PYTHON VULNERABILITIES

Implement reliable detection for:

## SQL Injection

Examples:

```python
query = "SELECT * FROM users WHERE id=" + user_id
cursor.execute(query)
```

and:

```python
query = f"SELECT * FROM users WHERE id={user_id}"
cursor.execute(query)
```

Finding:

```text
SQL Injection
CWE-89
HIGH
```

---

## Command Injection

Detect:

```python
os.system(user_input)
```

```python
os.popen(user_input)
```

```python
subprocess.run(user_input, shell=True)
```

```python
subprocess.call(user_input, shell=True)
```

Finding:

```text
Command Injection
CWE-78
CRITICAL
```

---

## Dangerous eval

Detect:

```python
eval(user_input)
```

Finding:

```text
Code Injection
CWE-95
CRITICAL
```

---

## Insecure Deserialization

Detect:

```python
pickle.loads(data)
```

Finding:

```text
Insecure Deserialization
CWE-502
HIGH
```

---

## Hardcoded Credentials

Detect obvious patterns:

```python
password = "admin123"
api_key = "..."
secret_key = "..."
```

Finding:

```text
Hardcoded Credentials
CWE-798
HIGH
```

Do not flag every normal string.

---

## Path Traversal

Detect suspicious patterns such as:

```python
open("/uploads/" + filename)
```

or:

```python
file_path = base_path + user_input
open(file_path)
```

Finding:

```text
Path Traversal
CWE-22
HIGH
```

# 24. RECOMMENDED FIX

Show before/after.

### Vulnerable

```python
query = f"SELECT * FROM users WHERE id={user_id}"
cursor.execute(query)
```

### Recommended

```python
cursor.execute(
    "SELECT * FROM users WHERE id=%s",
    (user_id,)
)
```

Explain:

> Parameterized queries keep user input separate from SQL instructions.
